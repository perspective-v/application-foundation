`PerspectiveV.EntityFramework` targets `net10.0`, references `Microsoft.EntityFrameworkCore` 10.0.6 and `PerspectiveV.Common`, and contains EF Core helpers plus three repository API generations. The package does not create a `DbContext`, configure a provider, register repositories, or define a unit of work. Public types are in the `PerspectiveV.EntityFramework.Extensions`, `PerspectiveV.EntityFramework.Repository.Interfaces`, `PerspectiveV.EntityFramework.Repository.Implementation`, and versioned repository namespaces. Source paths below are relative to the repository root.

## Query and context extensions

### `EfProperty`

Namespace: `PerspectiveV.EntityFramework.Extensions`; source: `PerspectiveV.EntityFramework/Extensions/EfCoreExtensions.cs`.

| Public member | Signature and behavior |
| --- | --- |
| `Property` | `Expression Property(Expression entity, string propertyName, Type propertyType)`. Builds a call to `EF.Property<propertyType>(entity, propertyName)`, suitable for query expressions that need a property selected by name. |

### `EfCoreExtensions`

Namespace: `PerspectiveV.EntityFramework.Extensions`; source: `PerspectiveV.EntityFramework/Extensions/EfCoreExtensions.cs`.

| Public member | Signature and behavior |
| --- | --- |
| `ByIdDynamic<TEntity>` | `Expression<Func<TEntity, bool>> ByIdDynamic<TEntity>(object id)`. Builds an `Id` equality expression using the detected `IEntity<Guid>`, `IEntity<int>`, `IEntity<long>`, or `IEntity<string>` contract. Unsupported entity ID contracts throw `NotSupportedException`; `id` must have the detected runtime type. |
| `ByTId<TEntity, TId>` | `Expression<Func<TEntity, bool>> ByTId<TEntity, TId>(TId id)`. Builds `x.Id == id` without an `IEntity<TId>` constraint or type conversion. `TEntity` must expose a compatible `Id` property. |
| `IsDeleted<TEntity>` | `Expression<Func<TEntity, bool>> IsDeleted<TEntity>(bool getSoftDeleted)`. Compares `IsDeleted` to the supplied flag; `false` selects active rows and `true` selects deleted rows. A nullable-bool property is coalesced to `false` before comparison. |
| `HasClientId<TEntity>` | `Expression<Func<TEntity, bool>> HasClientId<TEntity>(string clientId)`. Intended to compare `AppClientId` with the supplied value. The shared `IAppClient.AppClientId` contract is `Guid?`, so the current string comparison has mismatched expression types and throws when the expression is built for that contract. |
| `NotDeleted<TEntity>` | `Expression<Func<TEntity, bool>> NotDeleted<TEntity>() where TEntity : ISoftDeletable`. Builds a predicate requiring `IsDeleted == false`. |
| `ToNameValuePair<TEntity, TId>` | `Expression<Func<TEntity, NameValuePair<TId>>> ToNameValuePair<TEntity, TId>() where TEntity : class, INamedEntity<TId>`. Projects `Id` to `Value` and `Name` to `Name`, substituting `"No Name"` for a null name. |

The repository uses `ByTId` for its current ID lookup and `ByIdDynamic` for current delete/purge-by-ID operations. The dynamic helper's supported ID set is narrower than `IEntity<T>` in `PerspectiveV.Primitives`.

### `DbContextExtensions`

Namespace: `PerspectiveV.EntityFramework.Extensions`; source: `PerspectiveV.EntityFramework/Extensions/DbContextExtensions.cs`.

| Public member | Signature and behavior |
| --- | --- |
| `DetachLocal<T>` | `void DetachLocal<T>(this DbContext context, T t, string entryId) where T : class, IEntity`. Searches `context.Set<T>().Local` and detaches the first entity whose `Id.Equals(entryId)`. `t` is not used. Since `IEntity.Id` is `Guid` while `entryId` is `string`, ordinary GUID IDs do not match this comparison. |
| `DetachLocalObject<T>` | `void DetachLocalObject<T>(this DbContext context, T t, string entryId) where T : class`. If `t` implements one of the checked entity contracts, searches the local set by `((IEntity)x).Id.ToString() == entryId` and detaches the first match. The check recognizes several `IEntity<T>` types, but the predicate casts to non-generic `IEntity` (`Guid`); a matching non-Guid implementation can therefore fail with `InvalidCastException`. |
| `ClearChanges` | `void ClearChanges(this DbContext ctx)`. Detaches every tracked Added, Modified, or Deleted entry. It does not undo database writes already saved and leaves Unchanged entries tracked. |

## Current generic repository

The current contract and implementation live in `PerspectiveV.EntityFramework.Repository.Interfaces` and `PerspectiveV.EntityFramework.Repository.Implementation`. The implementation requires reference-type entity/model types and a `DbContext` subclass; the interface itself declares no generic constraints.

### `RepositoryAsync<IdType, EntityType, ModelType, DbContextType>`

Source: `PerspectiveV.EntityFramework/Repository/Implementation/RepositoryAsync.cs`.

```csharp
public abstract class RepositoryAsync<IdType, EntityType, ModelType, DbContextType>(
    DbContextType db,
    IProjectionMapper<IdType, EntityType, ModelType> mapper)
    : IRepositoryAsync<IdType, EntityType, ModelType, DbContextType>
    where ModelType : class
    where EntityType : class
    where DbContextType : DbContext;
```

The primary constructor stores the context and mapper. A concrete repository normally derives from this type, supplies its entity/model/context types, and is registered by the consuming application. Mapping is delegated to `IProjectionMapper<IdType, EntityType, ModelType>` from `PerspectiveV.Common.Mapper`; the mapper's query projection must be translatable by the selected EF provider.

| Member group | Runtime behavior |
| --- | --- |
| `GetAsync` | Starts from `DbContext.Set<EntityType>()`; queries are no-tracking unless `trackable` is true. Applies the predicate, sort options, and include. With no sort terms, the fallback constructs `OrderBy(e => EF.Property<EntityType>(e, "Id"))`; because `EntityType` is used as the property value type, verify that the provider can translate this for the entity's actual ID type. The non-generic overload defaults to mapper projection, or uses `select`; the generic overload maps when `TResult == ModelType`, casts entities when `TResult == EntityType`, and otherwise attempts an in-memory cast of each entity. A mismatched `TResult` can throw. Custom selectors are `Func` delegates and run through LINQ-to-Objects enumeration rather than being translated as query projections. For soft-deletable entities, the non-generic path excludes deleted rows when `getSoftDeleted` is false and includes both states when true; the generic overload always filters `IsDeleted == getSoftDeleted`, so true returns only deleted rows. |
| `PagedAsync` | Applies the optional predicate, search and sort options, then counts before pagination. With a soft-deletable entity, false excludes deleted rows; true skips the soft-delete predicate and can return both states. Offset defaults to 0 and limit to `int.MaxValue`; `Skip`/`Take` are applied only when a `PagingOptions` instance is supplied. Includes are added after pagination; results are projected by `select` or the mapper and returned with `ItemsCount`, `TotalItemsCount`, `Offset`, and `Limit`. A custom selector is a `Func` delegate and is enumerated client-side rather than translated by EF. |
| `GetSingleOrDefaultAsync` | Applies include, optional predicate, no-tracking by default, and the soft-delete filter when false; true includes both states. Uses `SingleOrDefaultAsync`, so duplicate matches throw. A found row is passed through `Activator.CreateInstance<ModelType>()` before mapper assignment, requiring a public parameterless model constructor. |
| `GetFirstOrDefaultAsync` | Same mapping, tracking, include, and soft-delete behavior as the single variant, but selects with `FirstOrDefaultAsync`. A found row also requires `ModelType` to have a public parameterless constructor because of the `Activator.CreateInstance` call. |
| `GetQueryable` | Returns the entity query with optional include and no-tracking by default. It does not apply soft-delete filtering, predicates, or sorting; callers own those clauses. |
| `GetByIdAsync` | Uses `ByTId` only when the entity implements one of the recognized entity contracts, applies optional include, and maps a match. If the entity is not recognized as an `IEntity` type, no ID predicate is created and the first row can be returned. When `getSoftDeleted` is false it excludes deleted rows; true disables that filter and includes both states. |
| `GetCountAsync` | Counts the optional predicate over a no-tracking set. It does not automatically exclude soft-deleted rows. |
| `CreateAsync` | Opens a transaction, processes each input separately, sets `IAuditable.CreatedDate` to UTC when the entity implements `IAuditable`, marks the entity Added, saves after each item, and maps each saved entity. It does not set `CreatedBy`. The single-item overload returns the first result from the list overload. |
| `UpdateAsync` | Opens a transaction, detaches a local matching entity for recognized entity types, sets `IAuditable.UpdatedDate` to UTC, marks the input Modified, saves after each item, and maps each saved entity. It does not set `UpdatedBy`. The local detach helper has the ID-cast caveat described above. |
| `TransactionAsync` | Begins a transaction, invokes the optional callback with the active context, commits, then detaches pending Added/Modified/Deleted entries via `ClearChanges`. It does not call `SaveChanges` for the callback; the callback must save its own work. Exceptions trigger rollback and are rethrown. |
| `DeleteAsync` | This is a soft-delete-style update, not a physical delete. Explicit `items` take precedence; otherwise `id` takes precedence over `where`. It sets `IsDeleted = true` when the type implements `ISoftDeletable`, marks each entity Modified, saves each one, and returns mapped models. For other entities it still marks rows Modified without setting a deletion flag. The single-result overload calls `First()` and throws if nothing matched. ID selection uses `ByIdDynamic`, which supports only Guid, int, long, or string IDs. |
| `PurgeAsync` | Marks explicit entities or entities selected by ID/predicate as EF Deleted, saves each one, and returns `true` after the transaction even if no rows matched. ID takes precedence over the predicate. This is the physical-delete operation; it does not apply a soft-delete filter. ID selection uses the same limited `ByIdDynamic` helper. |

The repository rethrows query and persistence exceptions without wrapping them. Write groups use transactions and roll back on failure. The only automatically written audit fields are `CreatedDate` and `UpdatedDate`; actor identity belongs to the calling layer.

`RepositoryAsync<EntityType, DbContextType>(DbContextType db)` uses synchronous `ToList()` materialization inside its `GetAsync`/`PagedAsync` task methods, does not map through `IProjectionMapper`, and does not write audit fields. Soft-delete filtering in list and paged methods compares `IsDeleted` to `getSoftDeleted`; the first/single methods exclude deleted rows only when no custom predicate is supplied. `GetQueryable` and `GetCountAsync` do not apply that filter. `SoftDeleteAsync` sets `IsDeleted = true` for soft-deletable inputs and otherwise marks them Modified. Explicit-item `DeleteAsync` physically deletes; the ID/predicate branch currently materializes matching rows but then loops the empty `items` parameter, so it does not delete those matches. There is no purge operation in this API.

## Composition and caller expectations

- Implement a concrete `DbContext`, configure the provider and connection, and register it in the consuming application.
- Register a concrete repository and expose it through the unit-of-work contract if a Web base controller resolves it. The expected property name is `{EntityType.Name}Service`.
- Supply `IProjectionMapper<IdType, EntityType, ModelType>` and aligned query projection expressions. `GetQueryable` deliberately returns raw entities and does not apply the repository's soft-delete convention.
- Search and sort use `PerspectiveV.Common.Paging` options and the model/entity property allowlists from `PerspectiveV.Common.Paging.Attributes`. Validate untrusted inputs at the API boundary; direct repository calls do not run MVC validation.
- Decide whether `DeleteAsync` should mean soft deletion for the entity. It physically removes data only through `PurgeAsync` in the current API; non-soft-deletable types are merely marked Modified by `DeleteAsync`.
