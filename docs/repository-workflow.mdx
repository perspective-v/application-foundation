## Build locally

Install the .NET 10 SDK, then run these commands from the repository root:

```powershell
dotnet restore
dotnet build PerspectiveVShell.sln -c Release
```

The solution contains the four package projects and currently has no test project.

## Package versions

The package versions come from each `.csproj`: the three lower-level packages are `10.0.0-alpha.1`, and `PerspectiveV.Web` is `10.0.0-alpha.2`. Check the package feed before selecting a version; project files describe this source checkout, not necessarily what has been published.

## Publishing configuration

The [GitHub Actions workflow](https://github.com/perspective-v/application-foundation/blob/main/.github/workflows/publish-nuget.yml) runs on pushes to the `deploy/feed` branch. It restores and builds the solution with the .NET 10 SDK, packs the four projects, then pushes each generated `.nupkg` to the feed URL provided by `NUGET_FEED_URL`.

Before the first run, create the `nuget-publish` environment in GitHub and add these environment secrets:

| Secret | Value |
| --- | --- |
| `NUGET_FEED_URL` | Gitea NuGet v3 feed URL. |
| `REGISTRY_USERNAME` | Username for a Gitea CI account with package write access in the `perspective-v` organization. |
| `REGISTRY_PASSWORD` | That account's Gitea access token with the `write:package` scope. |

The workflow stops with an error if any of these secrets is missing. It configures the NuGet source on the runner and does not use the ignored local `nuget.config`, `azure-pipelines.yml`, or `publish-nuget-*.bat` files.

Gitea rejects a package when the same package ID and version already exist. Increase the relevant `.csproj` version before publishing changed content, and verify each version on the registry afterward. See the [Gitea NuGet registry guide](https://docs.gitea.com/usage/packages/nuget) for registry behavior.

## Release checks for maintainers

1. Confirm package versions and dependency references in all four project files.
2. Run the Release build and inspect the produced `.nupkg` files.
3. Confirm the `nuget-publish` environment contains the three required secrets and has any intended reviewer gate.
4. Push the release commit to `deploy/feed` and verify the published package versions in Gitea.
